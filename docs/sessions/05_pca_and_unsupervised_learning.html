5.2 Theory (≈45 min)

5.2.1 1. From one variable to many

Each sample now has one value per metabolite. For the analyses of today, the table must have one row per sample and one column per metabolite: a matrix. Your data file is long (one row per sample and metabolite, as in Session 4), so the first step is pivot_wider(), the reverse of the pivot_longer() you used in Session 4.

Two more steps before any multivariate method:

  • log-transform: concentrations go from 0.02 to about 190,000. On the raw scale, a few very abundant molecules would dominate everything. log10() turns ratios into differences: a molecule that doubles moves by the same amount, whether it is rare or abundant.
  • scale: each metabolite is centred and divided by its standard deviation, so that each one has the same weight in the analysis (scale. = TRUE in prcomp()).

5.2.2 2. Unsupervised: PCA and clustering

A PCA (principal component analysis) summarises the 34 columns into a few new axes, the principal components. PC1 is the direction along which the samples differ the most, PC2 the next one, at right angles, and so on. Three things to read:

  • the share of variance of each axis: how much of the differences between samples it captures;
  • the scores: where each sample falls on the axes (the usual PCA plot);
  • the loadings: how much each metabolite contributes to each axis, and in which direction.

A heatmap with clustering shows the whole matrix as colours, and reorders rows and columns so that similar ones sit next to each other. The trees (dendrograms) show the groups found.

In the practical, you first run a PCA on data you know without any biology: 41 decathlon performances, 10 events each. You will see the axes rediscover the best athletes, and why scaling matters when the variables are in different units (seconds and metres).

Both are unsupervised: they never see your labels (water, heat). If the samples still group by condition, the condition is a major source of variation in the data.

5.2.3 3. Supervised: PLS-DA, and why it must be validated

A PLS-DA (partial least squares discriminant analysis) is told the groups, and looks for the combination of metabolites that best separates them. It is useful to find which molecules distinguish two conditions, but it is dangerous: with many variables and few samples, it can separate any groups, even groups drawn at random. A separation on the data the model learned from proves nothing.

The answer is cross-validation: hide part of the samples, train the model on the rest, predict the hidden samples, repeat. Only the accuracy on samples the model did not see tells you whether the separation is real. You will see this trap with your own eyes in block D.

5.2.4 4. Many tests at once: the volcano plot

You can also test each metabolite on its own: one t-test per molecule, as in Session 4. With 34 tests at the 5% level, you expect about 1 or 2 “significant” results by chance alone. Correcting the p-values (here with the Benjamini-Hochberg method, which controls the false discovery rate) keeps that under control.

A volcano plot shows all the tests at once: the effect on the x axis (log2 fold change: positive means higher under drought), the evidence on the y axis (−log10 of the adjusted p-value: the higher, the stronger).

Which method, when?

Your question Method In R Supervised?
What are the main patterns in the samples? Do they group by condition? PCA prcomp() no
Which samples and which variables look alike? heatmap with clustering pheatmap() no
Which combination of variables separates known groups? PLS-DA, always with cross-validation plsda(), perf() yes
Which variables change between two groups, one by one? one test per variable + FDR, volcano plot t.test(), p.adjust() (it is a test)

5.3 Your R toolbox

New tools today, on top of the Session 4 toolbox (still valid: see the Session 4 R toolbox).

  • tidyr: long → wide
  • PCA (base R)
  • pheatmap
  • mixOmics
  • ggrepel

pivot_wider() is the reverse of pivot_longer(): it spreads one column into many.

root_wide <- root_long %>%
  pivot_wider(names_from = metabolite, values_from = log_conc)
  • names_from: the column whose values become the new column names (here: the metabolite names);
  • values_from: the column that fills the new columns (here: the log concentrations).

Then select(-sample, ...) and as.matrix() keep the numbers only, as a matrix, and rownames() puts the sample names back on the rows.

Common mistake. Keeping a column that differs inside a sample (such as the raw concentration next to log_conc): pivot_wider() then cannot put one sample on one row. Select only the columns you need before pivoting.

prcomp() is part of R itself: no package needed.

Code What it gives
prcomp(matrix, scale. = TRUE) the PCA, each variable scaled
summary(pca)$importance[2, ] the share of variance of each axis
pca$x the scores: one row per sample, one column per axis
pca$rotation the loadings: one row per variable, one column per axis

Reading the loadings. A metabolite with a large negative loading on PC1 is high in the samples on the left of the PCA plot; a large positive loading, high on the right.

Common mistake. Forgetting scale. = TRUE: the variables with the largest numbers then decide everything.

pheatmap(t(root_matrix), scale = "row", annotation_col = annotation,
         show_colnames = FALSE, fontsize_row = 7)
  • t() turns the matrix around: metabolites in rows, samples in columns;
  • scale = "row": each metabolite is shown as “above or below its own average” (z-score), otherwise the most abundant ones would fill the colour scale;
  • annotation_col: a small table, one row per sample (with the sample names as row names), whose columns become coloured bars on top;
  • the trees on the left and on top are the clustering: they are computed from the data, not from the annotation.

The reference package for PLS-DA (and much more) in biology.

Code What it does
plsda(matrix, groups, ncomp = 2) fits a PLS-DA with 2 components
plotIndiv(model, ellipse = TRUE, legend = TRUE) the sample plot, with one ellipse per group
predict(model, matrix)$class$max.dist the predicted group of each sample
perf(model, validation = "Mfold", folds = 4, nrepeat = 10) cross-validation: 4 folds, repeated 10 times
perf(...)$error.rate$BER the balanced error rate, per component (accuracy = 1 − error)

Install once, load every time. BiocManager::install("mixOmics", update = FALSE) runs once, in the Console (block A0). library(mixOmics) goes at the top of every report. Never put an install line in your workbook: every Render would install it again.

Common mistake: load it first. mixOmics loads another package (MASS) that also has a function called select(). Whatever is loaded last wins. So load mixOmics before the tidyverse; otherwise select() stops working, with a confusing error (“unused argument”).

Documentation. mixomics.org

geom_text_repel() writes text labels on a plot and moves them so that they do not overlap, unlike geom_text().

geom_text_repel(data = slice_min(root_tests, p_adjusted, n = 10),
                aes(label = metabolite), size = 3)

data = ... labels only some of the points: here, the 10 with the smallest adjusted p-values (slice_min(), from dplyr).

5.4.6 D. Guided: with labels, then one test per molecule (16:35-17:10, pairs)

D1. PLS-DA with the real labels.

root_plsda <- plsda(root_matrix, root_wide$water, ncomp = 2)

plotIndiv(root_plsda, ellipse = TRUE, legend = TRUE,
          title = "Root, PLS-DA with the real labels")

D2. The trap. Now give the PLS-DA labels that mean nothing: the same “drought” and “watered” labels, mixed at random with sample(). Let it use 10 components, then ask how well it classifies the samples it learned from:

set.seed(1)
shuffled <- sample(root_wide$water)
root_plsda_shuffled <- plsda(root_matrix, shuffled, ncomp = 10)

predicted <- predict(root_plsda_shuffled, root_matrix)$class$max.dist[, 10]
mean(predicted == shuffled)

set.seed(1) makes the random draw the same for everyone, so that you can compare your numbers.

D3. Cross-validation. The same two models, now judged on samples they did not learn from:

set.seed(1)
cv_shuffled <- perf(root_plsda_shuffled, validation = "Mfold", folds = 4, nrepeat = 10)
1 - cv_shuffled$error.rate$BER[10, "max.dist"]

set.seed(1)
cv_real <- perf(root_plsda, validation = "Mfold", folds = 4, nrepeat = 10)
1 - cv_real$error.rate$BER[2, "max.dist"]
NoteCheckpoint

D2: the model learns the random labels almost perfectly (more than 90% correct on its own data). D3: on samples it did not see, the same model is no better than tossing a coin (around 50%), while the model with the real labels stays above 90%. Your exact numbers can differ slightly with another version of mixOmics.

D4. One test per molecule. The t-test of Session 4, run on each metabolite, then the correction:

root_tests <- metabolites %>%
  filter(organ == "root") %>%
  group_by(metabolite, panel) %>%
  summarise(log2_fold_change = log2(mean(concentration[water == "drought"]) /
                                    mean(concentration[water == "watered"])),
            p_value = t.test(log10(concentration) ~ water, var.equal = TRUE)$p.value,
            .groups = "drop") %>%
  mutate(p_adjusted = p.adjust(p_value, method = "BH"))

log2_fold_change: 1 means twice as high under drought, −1 half as high, 0 no change.

D5. The volcano plot.

ggplot(root_tests, aes(x = log2_fold_change, y = -log10(p_adjusted), colour = panel)) +
  geom_point(size = 2) +
  geom_hline(yintercept = -log10(0.05), linetype = "dashed") +
  geom_vline(xintercept = 0) +
  geom_text_repel(data = slice_min(root_tests, p_adjusted, n = 10),
                  aes(label = metabolite), size = 3, show.legend = FALSE)

## Theory (≈45 min)

### 1. From one variable to many

Each sample now has one value per metabolite. For the analyses of today, the table must
have **one row per sample and one column per metabolite**: a **matrix**. Your data file
is long (one row per sample *and* metabolite, as in Session 4), so the first step is
`pivot_wider()`, the reverse of the `pivot_longer()` you used in Session 4.

Two more steps before any multivariate method:

- **log-transform**: concentrations go from 0.02 to about 190,000. On the raw scale, a few very
  abundant molecules would dominate everything. `log10()` turns ratios into differences:
  a molecule that doubles moves by the same amount, whether it is rare or abundant.
- **scale**: each metabolite is centred and divided by its standard deviation, so that
  each one has the same weight in the analysis (`scale. = TRUE` in `prcomp()`).

### 2. Unsupervised: PCA and clustering

A **PCA** (principal component analysis) summarises the 34 columns into a few new axes,
the **principal components**. PC1 is the direction along which the samples differ the
most, PC2 the next one, at right angles, and so on. Three things to read:

- the **share of variance** of each axis: how much of the differences between samples
  it captures;
- the **scores**: where each sample falls on the axes (the usual PCA plot);
- the **loadings**: how much each metabolite contributes to each axis, and in which
  direction.

A **heatmap with clustering** shows the whole matrix as colours, and reorders rows and
columns so that similar ones sit next to each other. The trees (dendrograms) show the
groups found.

In the practical, you first run a PCA on data you know without any biology: 41 decathlon
performances, 10 events each. You will see the axes rediscover the best athletes, and why
scaling matters when the variables are in different units (seconds and metres).

Both are **unsupervised**: they never see your labels (`water`, `heat`). If the samples
still group by condition, the condition is a major source of variation in the data.

### 3. Supervised: PLS-DA, and why it must be validated

A **PLS-DA** (partial least squares discriminant analysis) is told the groups, and looks
for the combination of metabolites that **best separates** them. It is useful to find
which molecules distinguish two conditions, but it is dangerous: with many variables
and few samples, it can separate **any** groups, even groups drawn at random. A
separation on the data the model learned from proves nothing.

The answer is **cross-validation**: hide part of the samples, train the model on the
rest, predict the hidden samples, repeat. Only the accuracy on samples the model did not
see tells you whether the separation is real. You will see this trap with your own eyes
in block D.

### 4. Many tests at once: the volcano plot

You can also test each metabolite on its own: one t-test per molecule, as in Session 4.
With 34 tests at the 5% level, you expect about 1 or 2 "significant" results **by chance
alone**. Correcting the p-values (here with the Benjamini-Hochberg method, which controls
the **false discovery rate**) keeps that under control.

A **volcano plot** shows all the tests at once: the effect on the x axis (log2 fold
change: positive means higher under drought), the evidence on the y axis
(−log10 of the adjusted p-value: the higher, the stronger).

**Which method, when?**

| Your question | Method | In R | Supervised? |
|---|---|---|---|
| What are the main patterns in the samples? Do they group by condition? | PCA | `prcomp()` | no |
| Which samples and which variables look alike? | heatmap with clustering | `pheatmap()` | no |
| Which combination of variables separates known groups? | PLS-DA, **always with cross-validation** | `plsda()`, `perf()` | yes |
| Which variables change between two groups, one by one? | one test per variable + FDR, volcano plot | `t.test()`, `p.adjust()` | (it is a test) |

::: panel-tabset
## tidyr: long → wide

`pivot_wider()` is the reverse of `pivot_longer()`: it spreads one column into many.

```r
root_wide <- root_long %>%
  pivot_wider(names_from = metabolite, values_from = log_conc)
```

- `names_from`: the column whose values become the **new column names** (here: the
  metabolite names);
- `values_from`: the column that fills the new columns (here: the log concentrations).

Then `select(-sample, ...)` and `as.matrix()` keep the numbers only, as a matrix, and
`rownames()` puts the sample names back on the rows.

**Common mistake.** Keeping a column that differs inside a sample (such as the raw
`concentration` next to `log_conc`): `pivot_wider()` then cannot put one sample on one
row. Select only the columns you need before pivoting.

## PCA (base R)

`prcomp()` is part of R itself: no package needed.

| Code | What it gives |
|---|---|
| `prcomp(matrix, scale. = TRUE)` | the PCA, each variable scaled |
| `summary(pca)$importance[2, ]` | the share of variance of each axis |
| `pca$x` | the **scores**: one row per sample, one column per axis |
| `pca$rotation` | the **loadings**: one row per variable, one column per axis |

**Reading the loadings.** A metabolite with a large negative loading on PC1 is high in
the samples on the left of the PCA plot; a large positive loading, high on the right.

**Common mistake.** Forgetting `scale. = TRUE`: the variables with the largest numbers
then decide everything.

## pheatmap

```r
pheatmap(t(root_matrix), scale = "row", annotation_col = annotation,
         show_colnames = FALSE, fontsize_row = 7)
```

- `t()` turns the matrix around: metabolites in rows, samples in columns;
- `scale = "row"`: each metabolite is shown as "above or below its own average"
  (z-score), otherwise the most abundant ones would fill the colour scale;
- `annotation_col`: a small table, one row per sample (with the sample names as row
  names), whose columns become coloured bars on top;
- the trees on the left and on top are the **clustering**: they are computed from the
  data, not from the annotation.

## mixOmics

The reference package for PLS-DA (and much more) in biology.

| Code | What it does |
|---|---|
| `plsda(matrix, groups, ncomp = 2)` | fits a PLS-DA with 2 components |
| `plotIndiv(model, ellipse = TRUE, legend = TRUE)` | the sample plot, with one ellipse per group |
| `predict(model, matrix)$class$max.dist` | the predicted group of each sample |
| `perf(model, validation = "Mfold", folds = 4, nrepeat = 10)` | cross-validation: 4 folds, repeated 10 times |
| `perf(...)$error.rate$BER` | the balanced error rate, per component (accuracy = 1 − error) |

**Install once, load every time.** `BiocManager::install("mixOmics", update = FALSE)`
runs once, in the Console (block A0). `library(mixOmics)` goes at the top of every
report. Never put an install line in your workbook: every Render would install it again.

**Common mistake: load it first.** mixOmics loads another package (MASS) that also has a
function called `select()`. Whatever is loaded **last** wins. So load `mixOmics`
**before** the tidyverse; otherwise `select()` stops working, with a confusing error
("unused argument").

**Documentation.** [mixomics.org](https://mixomics.org/)

**D2. The trap.** Now give the PLS-DA labels that mean **nothing**: the same "drought"
and "watered" labels, mixed at random with `sample()`. Let it use 10 components, then ask
how well it classifies the samples it learned from:

```r
set.seed(1)
shuffled <- sample(root_wide$water)
root_plsda_shuffled <- plsda(root_matrix, shuffled, ncomp = 10)

predicted <- predict(root_plsda_shuffled, root_matrix)$class$max.dist[, 10]
mean(predicted == shuffled)
```

`set.seed(1)` makes the random draw the same for everyone, so that you can compare your
numbers.

**D3. Cross-validation.** The same two models, now judged on samples they did not learn
from:

```r
set.seed(1)
cv_shuffled <- perf(root_plsda_shuffled, validation = "Mfold", folds = 4, nrepeat = 10)
1 - cv_shuffled$error.rate$BER[10, "max.dist"]

set.seed(1)
cv_real <- perf(root_plsda, validation = "Mfold", folds = 4, nrepeat = 10)
1 - cv_real$error.rate$BER[2, "max.dist"]
```

::: callout-note
## Checkpoint

D2: the model learns the **random** labels almost perfectly (more than 90% correct on
its own data). D3: on samples it did not see, the same model is no better than tossing
a coin (around 50%), while the model with the real labels stays above 90%. Your exact
numbers can differ slightly with another version of mixOmics.
:::

**D4. One test per molecule.** The t-test of Session 4, run on each metabolite, then the
correction:

```r
root_tests <- metabolites %>%
  filter(organ == "root") %>%
  group_by(metabolite, panel) %>%
  summarise(log2_fold_change = log2(mean(concentration[water == "drought"]) /
                                    mean(concentration[water == "watered"])),
            p_value = t.test(log10(concentration) ~ water, var.equal = TRUE)$p.value,
            .groups = "drop") %>%
  mutate(p_adjusted = p.adjust(p_value, method = "BH"))
```

`log2_fold_change`: 1 means twice as high under drought, −1 half as high, 0 no change.

**D5. The volcano plot.**
